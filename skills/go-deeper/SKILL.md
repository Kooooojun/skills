# Go Deeper：更深，不是更大

同一個問題，用更硬的證據、更原始的材料、更可驗證的方法回答。不加主題；
改寫後範圍通常一樣或更窄。

先找出使用者真正要的結果（報告？程式？決策？），並讀原任務附的檔案、連結或 repo。答案要落在**這個**任務上：換個任務還成立的句子就是太泛，重寫。
提到的檔案、指令、資料表、網址，能查就確認存在；查不到標「未確認」，不要編。

## 四個問題

1. **專家會多做的事**（2–4 項）：老手反射性做、新手不知道的動作，不是「更仔細」。
   每項說明不做會錯在哪。例：先把數字跟原始財報對帳；先重現 bug 再改程式。
2. **最原始的材料**：原始資料、條文原文、log、原始碼、交易明細、官方公告，給確切位置。
   對照目前依賴的二手材料（摘要、部落格、聚合統計、AI 上一輪回答）遺失或扭曲了什麼。
3. **方法與工具**：有名字、能執行（對帳、逐案 trace、敏感度分析、樣本外回測、diff 官方結果）；
   指名指令、函式庫或腳本，並說明各自回答哪個子問題。
4. **外部驗證**：「你我覺得對」不算。用官方／第三方紀錄、可重跑且可存檔的檢查、
   事前寫下的可證偽預測，或獨立來源算出同一個數。寫清楚看到什麼算對、什麼算錯。

## 輸出

依序給四題答案，再給改寫後的 prompt（code block）：

```
目標：<原任務，一句話，範圍不放大>

起點材料：<最原始的來源與確切位置>；不要用 <已消化材料>。

做法：
1. <專家會做的事／方法，含工具與指令>
2. ...

驗收：<外部證據> 顯示 <通過條件> 才算完成。
交付時附上 <可重現的產物：檔案、指令、輸出>。
若材料取不到或驗收不過，直接說明卡在哪，不要用推測補。

可延伸（本次不做）：<真的需要但超出原範圍的事，沒有就刪>
```

保留使用者原本的目標、限制與語氣；「深入分析」這類詞換成可檢查的具體動作。

最後一行問：「要我照這版直接做嗎？」使用者說要，就照改寫版執行，交付時逐條對照「驗收」回報。

## 範例

原 prompt：「幫我分析這檔股票最近為什麼被列注意股。」

- 專家會多做：逐條對照被觸發的款次與門檻實際數值，不看新聞說法；檢查是否差一點也觸發別款。
- 原始材料：交易所注意股公告原文、該款條文、當日成交明細；不用財經新聞轉述。
- 方法：用條文公式逐日重算，找出觸發日的數字與門檻差距。
- 外部驗證：重算結果與公告的款次、日期逐筆一致；不一致就列出差異與原因。
