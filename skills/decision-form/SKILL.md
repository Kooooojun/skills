# decision-form：把待決問題做成問卷

使用者不想在終端機裡讀一大段再回答。把要他決定的事做成一頁一題的問卷，他在手機上點完、
複製答案貼回來，你照答案做。

## 流程

1. **讀本機設定**：`~/.config/decision-form/local.md` 存在就先讀，交付方式以它為準。範本見
   本資料夾的 `local.example.md`。
2. **只問真的要他決定的事**。查得到的事實先自己查，能從專案規則推出來的不要問。
   每題寫：
   - 一句白話的問題。
   - 2～4 行背景：決定需要的事實。查不到的寫「未確認」，不要猜。
   - 2～3 個選項，每個都寫出代價。你推薦的標 `rec`，理由寫在它的 `why`。
     「不確定，想討論」會自動加，不要自己寫。
   - 「要先做哪幾個」這種題目用複選（`multi`）。最後可以放一題自由填寫（`free`）：「還有別的想說嗎？」
3. **產生頁面**：把題目寫成 JSON（格式見下面「題目資料」），放在暫存資料夾，然後執行：
   ```
   python3 <這個 skill 的資料夾>/scripts/build_form.py questions.json form.html
   ```
   報錯就照訊息修 JSON。不要手改 HTML：模板負責跳脫文字、存答案、複製失敗時的備案。
4. **交付**：照 `local.md`。沒有 `local.md` 時，宿主能發網頁（例如 artifact）就發，否則給檔案的完整路徑。
   給網址前先確認打得開（例如 `curl` 回 200）。
5. **回覆要短**：給連結，每題一行標題，標出你推薦哪個。不要把問卷內容在對話裡再貼一次。

## 收到答案

使用者貼回來的文字長這樣（這是契約，模板和 `evals/expected.txt` 都照它）：

```
<標題>回覆（<日期>）
1. #101 要不要升級套件？ → A．升級
   備註：週五前做完
2. #102 報表放哪？ → （跳過）
3. #103 部署時間？ → 🤔 想討論
   備註：第一行
   第二行
4. 先修哪幾個？ → 勾選：#201 修登入、#203 修報表
5. 還有別的嗎？ → 見備註
   備註：沒了
```

- 每題一行：`題號. [ref ]題目 → 答案`。題目有 `ref`（票號、PR 號）就放在最前面。
- `X．選項`：照選項做。合併、部署、刪資料這類動作，原本要確認的照樣要確認，問卷不擴大授權。
- `🤔 想討論`：先回答備註裡的疑問，用兩三句話比較選項，再問一次。這題沒拍板前不要動手。
- `（跳過）`：不動，回報時列在「還沒決定」。
- `勾選：…`／`都不勾`：只做勾到的，照問卷列的順序。
- `見備註`：自由填寫題，備註就是使用者的指示。
- 備註和選項衝突時，以備註為準；看不懂就問。
- 答案的題目對不上你出的題（例如問卷改版過），用 `ref` 和題目文字比對，對不上就問。

## 題目資料

```json
{
  "title": "解票問答",
  "date": "2026-01-02",
  "key": "選填；同標題同日期要分開存答案時才給",
  "questions": [
    {
      "id": "101", "ref": "#101", "title": "要不要升級套件？",
      "pic": "📦", "cap": "選填：圖下的一句說明",
      "ctx": ["新版修了一個 bug。", "可能要改兩個呼叫處。"],
      "options": [
        { "k": "A", "label": "升級", "why": "修掉 bug，要改兩處。", "rec": true },
        { "k": "B", "label": "先不升", "why": "不用改，bug 還在。" }
      ]
    },
    {
      "id": "fix", "title": "小票：哪幾張先修？", "multi": true,
      "ctx": ["取消勾選的就先不碰。"],
      "items": [
        { "k": "201", "label": "#201 修登入", "why": "很小。" }
      ]
    },
    { "id": "more", "title": "還有別的想說嗎？", "free": true, "ctx": ["可以跳過。"] }
  ]
}
```

- 必填：`title`、`date`、每題的 `id`（不能重複）、`title`，以及 `options`／`multi`／`free` 三選一。
- `options`：2～3 個，代號 `k` 不能重複、不能用 `talk`，最多一個 `rec`。
- `multi`：`items` 至少一個，預設全部勾選。
- `pic` 用一兩個 emoji 當插圖就好；可省略。

## 測試

改模板或產生器後跑 E2E：用真的 Chrome 點完 `evals/fixture.json` 的問卷，剪貼簿要和
`evals/expected.txt` 逐字相同，也會確認格式錯的題目會被擋下。

```
uv run --with playwright python evals/e2e.py
```

需要本機有 Google Chrome。
